# 版本记录（财务内部在线工具）

版本格式：`v主版本.次版本.修订`。大版本 = 新增主要功能/新形态；次版本 = 功能或流程调整；修订 = 细节优化与修复。

> 注：v3.0.0 之前为控制台脚本时期，版本号依据 git 提交记录与脚本 docstring 重建（未逐次归档），仅 v2.0.0 为历史提交中明确标注的版本。

## v3.4.1（2026-08-12）— 优化收款组 OCR 速度

**修订**：收款组（模式 1）OCR 提速约 1.3 倍（弱 CPU 服务器实测）。

- RENDER_DPI 150→120：OCR 检测模型耗时随图片面积下降；发票四字段字号较大仍可清晰识别
- process_mode1 的 OCR 循环改多线程并行（ThreadPoolExecutor，worker=CPU 核数/2，上限 4）
- RapidOCR 线程安全已实测可共用单例并发推理；进度回调保持主线程更新

---

## v3.4.0（2026-08-12）— OCR 引擎更换为 RapidOCR，修复无 AVX CPU 崩溃

**次版本**：OCR 引擎从 PaddleOCR 换为 RapidOCR（onnxruntime）。

- 服务器 CPU（Intel Pentium Gold，无 AVX）上 PaddlePaddle 官方 wheel 运行必崩（SIGILL，退出码 132），导致 OCR 全部失败
- RapidOCR 跑同一套 PP-OCRv4 ONNX 模型（wheel 内置，无需运行时下载），识别效果基本一致；onnxruntime 支持 SSE4.2 老 CPU
- 镜像体积从 ~1.5GB 降到 ~600MB
- 金额识别正则兼容 OCR 输出的中文全角逗号（，）与英文半角逗号（,）
- requirements：paddleocr/paddlepaddle → rapidocr_onnxruntime==1.4.4

## v3.3.0（2026-08-11）— 收款组支持插入已有表格

**次版本**：恢复控制台版"把图片插入到已有表格"的完整流程，网页化交互。

- 收款组新增"插入已有表格（可选）"：上传 .xlsx 模板 → 后端读取其工作表 → 页面显示为**按钮**供点选 → 选方向/起始格 → 图片插入指定工作表后下载

- 不传模板时保持自动新建表格，两种方式并存
- 工作表按名称精确定位，中文表名正常（真实浏览器 UTF-8）

## v3.2.0（2026-08-11）— 收款组新增排版方向与起始位置

**次版本**：收款组（模式1）恢复"插入位置"选择能力（网页化交互）。

- 收款组上传区上方新增排版选项：排版方向（纵向/横向）+ 起始位置（默认 A1，可填如 C5）
- 纵向：图片沿列向下排、字段在图片右侧；横向：图片沿行向右排、字段在图片下方
- 起始格非法（如 5A）时给出提示并禁用制作按钮；后端复用原脚本 images_into_excel(direction, start_cell)
- 付款组不显示该选项；默认 纵向 + A1，与原行为一致

- 前端版本同步更新至 v3.1.0

## v3.0.0（2026-08-11）— 新增网页版在线工具

**大版本**：在控制台脚本基础上新增网页版，可在浏览器操作。

- 新增 `web/` 网页版（Vue 3 + Vite 前端 + FastAPI 后端）

  - 复用原脚本处理逻辑（import，不复制），保证控制台版与网页版行为一致
- 收款组输出由"插入已有 Excel 模板"简化为自动生成含图 Excel 并直接下载
- 原脚本 `pdf_to_images` 增加可选 `progress_cb` 参数（向后兼容，供网页版显示进度）
- 新增 `开发文档.md`、`web/README.md`
