# PDF 工具网页版 开发文档

- 项目：PDF 工具（网页版）
- 版本：v3.0.0
- 日期：2026-08-11
- 关联脚本：[pdf转图片.py](pdf转图片.py)（控制台版，v2.x）

---

## 一、需求背景

原 [pdf转图片.py](pdf转图片.py) 为控制台脚本，需通过拖拽 / 剪贴板粘贴路径的方式操作，对不熟悉终端的同事不友好，也不便多人共用。

**目标**：改造为网页版在线工具——

1. 前端用 **Vue 3 + Vite**，脚本里的功能模式 / 发票类型 / 选项做成网页按钮；
2. 用 **网页上传区域**（支持批量上传、拖拽）替代原脚本的"剪贴板导入路径"；
3. 上传后点"开始制作"，后台处理并实时显示进度条；
4. 处理完成直接在浏览器下载生成的 Excel 表格。

**已确认的关键决策**：Vite + Vue 3 标准工程；收款组输出"含图片的 Excel"；长任务用"后台任务 + 进度条轮询"。

## 二、功能清单

| 功能 | 模式 | 说明 | 输出 |
|---|---|---|---|
| PDF 转图片 + 发票识别 | 收款组（模式1） | 逐页渲染 PDF 为 PNG，OCR 识别发票号码/购买方/销售方/金额并重命名，嵌入 Excel | `发票图片表.xlsx`（含图片） |
| 发票明细识别 | 付款组（模式2）canexs | 识别 INVOICE / TRACKING NO. / 明细行 | `canexs发票明细表.xlsx` |
| 发票明细识别 | 付款组（模式2）精准 | Accuracy Customs Brokers 清关发票 | `精准发票明细表.xlsx` |

**相比控制台版的简化**：收款组原"插入已有 Excel 模板（选工作表/起始格/方向）"流程，简化为自动新建含图 Excel，处理完直接下载（符合"直接导出表格下载"的需求）。

## 三、系统架构

```
浏览器 (Vue 3 页面)
   │  HTTP / fetch
   ▼
FastAPI 后端（web/backend）
   ├─ app.py      接口路由 + 托管前端静态文件
   ├─ tasks.py    后台任务队列（单 worker 串行，避免 PaddleOCR 并发）
   └─ processor.py 复用 pdf转图片.py 的处理逻辑（import，不复制代码）
        │
        ▼
   pdf转图片.py（原脚本，仅给 pdf_to_images 增加可选 progress_cb）
```

- **后端**：FastAPI + uvicorn（均已安装，无需新增 Python 依赖）。
- **前端**：Vue 3 + Vite，`npm run build` 产物由 FastAPI 托管，单端口（8000）访问，内网离线可用。
- **任务模型**：上传后立即返回 `task_id`，前端每 1.2s 轮询一次状态；单个 worker 线程 FIFO 串行处理，进度写回任务表。

## 五、接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/tasks` | multipart 上传：`files[]`（多选 PDF）、`mode`（1收款组/2付款组）、`inv_type`（模式2：1 canexs / 2 精准）。返回 `{task_id, files}` |
| GET | `/api/tasks/{id}` | 轮询状态：`{status, current, total, message, filename, error}`（status: pending/processing/done/error） |
| GET | `/api/tasks/{id}/download` | 下载生成的 Excel（完成后可用） |
| GET | `/` `/assets/*` | 前端页面与静态资源（dist 存在时） |

**校验**：仅接受 `.pdf`；`mode`/`inv_type` 非法返回 400；无文件返回 400。

## 六、复用逻辑（关键）

`processor.py` 通过 `sys.path` 指向 `PDF转图片/` 后 `import pdf转图片 as tool`，直接调用原脚本函数，**不复制处理逻辑**，控制台版后续改进会自动同步到网页版：

| 复用的函数 | 用途 |
|---|---|
| `pdf_to_images(pdf, out, start_index, dpi, progress_cb)` | 渲染 PNG；`progress_cb` 为本版新增可选参数（向后兼容） |
| `extract_invoice_fields` / `rename_with_fields` | 收款组 OCR 识别 + 重命名 |
| `images_into_excel` | 收款组图片+字段嵌入 Excel |
| `extract_detail_from_pdfs` / `extract_jingzhun_from_pdfs` | 付款组明细识别 |
| `write_detail_excel` | 付款组写 Excel（含补零/列宽参数） |

**对原脚本的唯一改动**：`pdf_to_images` 增加可选参数 `progress_cb(stage, done, total)`，每渲染一页回调一次，默认 `None` 时行为不变。

## 七、部署与运行

```bash
# 1. 安装 Python 依赖（均已装好，无则执行）
pip install -r requirements.txt
pip install fastapi uvicorn python-multipart

# 2. 构建前端（仅在修改前端后需要）
cd web/frontend
npm install
npm run build

# 3. 启动后端（单进程，同时提供页面与接口）
cd web/backend
python run.py            # 默认 0.0.0.0:8000，内网可访问
# HOST=127.0.0.1 PORT=9000 python run.py   # 自定义

# 4. 浏览器访问
http://127.0.0.1:8000
```

**开发模式**（前端热更新）：

```bash
# 终端1：后端
cd web/backend && python run.py
# 终端2：前端（vite 代理 /api → 8000）
cd web/frontend && npm run dev   # 打开 http://127.0.0.1:5173
```

**说明**：
- 首次执行收款组会下载 PaddleOCR 模型（约几百 MB，需联网一次，之后走缓存）。
- 上传文件与生成结果存放在 `web/backend/.tmp/{task_id}/`，后端启动时自动清理 24 小时前的临时目录。

## 九、常见问题

- **点制作后一直"正在制作"**：OCR 首次运行或扫描件较多时耗时较长，属正常；页面会显示"正在识别发票字段 x/y 张…"。
- **任务失败"没有识别到任何明细"**：发票版式与所选类型不匹配（如把精准发票选成 canexs），请核对发票类型。
- **内网其他电脑打不开**：确认后端以 `0.0.0.0` 启动、防火墙放行 8000 端口，访问 `http://<服务器IP>:8000`。
