# 水单 PDF 自动核对归档

## 目标

提供一个不依赖网页的 Windows 脚本。每批运行时依次选择报销/付款 PDF 文件夹和水单文件夹；人民币只扫描所选目录当前一级文件。中信银行、招商银行、浦发银行外币是固定例外：读取 `银行名称` 第一层目录下、第二层日期目录中的 PDF；文件名含“回单”的作为水单，同级其他 PDF（例如付款审核）作为来源付款申请。每批结束会询问是否继续，选择“是”后才重新选择下一批文件夹。PDF 和水单均先按原图 OCR，仅原图没有识别出金额时才对该单张做一次 OpenCV 1.5 倍放大、局部对比度和二值化增强重试；控制台实时显示扫描数量、当前 OCR 文件、已识别金额、匹配和归档状态；日志中的金额统一为亮绿色加粗。

## 处理规则

- 来源 PDF：人民币读取“付款总额”或“汇款金额”右侧金额，以及“报销金额”“总费用金额”“借款金额”“申请金额”表头正下方同列的最近金额；不再读取单项“费用金额”，也不扫描表头后的其他字段数字；外币读取“付款总额”。中信银行日期子文件夹内、与回单同级的付款审核 PDF 也按此规则读取。
- 人民币水单：识别同图内的 `金额` 字段与 `CNY` 金额（兼容 OCR 文字顺序颠倒）、`付款金额`、`金额（小写）`、`汇款金额`后的金额、`金额` 字段后（兼容多种横线和分行 OCR）的负数金额、微信/零钱通支付成功或支付宝交易成功页中央负数金额、`汇款金额小写` 后的金额；兼容 OCR 将千分位逗号误读为点；匹配结果放入 `水单正常匹配`。
- 中信银行外币回单 PDF：放在 `中信银行/日期文件夹/`，仅处理文件名含“回单”的文件；文件名只用于筛选回单，金额必须从 PDF 正文的“购汇金额”和“现汇金额”字段读取 USD、CAD、GBP、EUR。两笔金额确实不同才相加；OCR 将同一笔金额重复关联到两个字段、导致两者完全相同时只取一次。再同另一份付款申请 PDF 的“付款总额”核对；唯一匹配的付款审核和回单在该日期文件夹内创建 `水单正常匹配` 并移入。
- 招商银行外币回单 PDF：放在 `招商银行/日期文件夹/`，仅处理文件名含“回单”的文件；文件名只用于筛选回单，金额必须从 PDF 正文“买入币种/金额”字段读取 USD、CAD、GBP、EUR，再同同级付款审核 PDF 的“付款总额”核对。唯一匹配的付款审核和回单在该日期文件夹内创建 `水单正常匹配` 并移入。
- 浦发银行外币回单 PDF：放在 `浦发银行/日期文件夹/`，仅处理文件名含“回单”的文件；按文件名中币种紧随的金额读取，例如 `回单-富皇USD28577.pdf` 读取 USD `28577`，再同同级付款审核 PDF 的“付款总额”核对。唯一匹配的付款审核和回单在该日期文件夹内创建 `水单正常匹配` 并移入；同金额多候选仍保留原名并追加 `.1`、`.2` 序号后移至 `异常`。
- 同目录中名称包含“提交的付款申请”的 PNG/JPG 等来源单据转图会自动跳过，不作为水单图片 OCR。
- 唯一匹配成功的一对保留各自原文件名进入正常归档；水单/回单只在其原名末尾追加付款申请文件名中以 `2026` 开头的审批编号。仅当同一金额的 PDF 与水单两边都存在多份候选、无法一一确认时，才统一移动至来源 PDF 文件夹下的 `异常文件夹`；未识别金额、读取失败、只有 PDF 或只有水单的文件保留在原位置，并写入处理报告。

## 输出与安全性

常规人民币的 `水单正常匹配`、`异常文件夹`、外币冲突专用的 `异常` 和 `水单匹配处理报告.csv` 均创建在所选的来源 PDF 文件夹中；中信银行、招商银行、浦发银行日期目录内同级匹配成功的文件则在该日期目录创建 `水单正常匹配`。付款申请保留原名；水单或银行回单保留原名并在末尾追加付款申请名中以 `2026` 开头的审批编号，例如 `回单-富皇-USD-6666-202609210001.pdf`。外币同金额多候选文件会保留原始名称，并在扩展名前追加序号，例如 `回单-富皇-USD-6666.1.pdf`、`回单-富皇-USD-6666.2.pdf`；目标已存在同名文件时自动保留两份文件，不会覆盖。

## 验证

1. 使用 `py_compile` 验证脚本语法。
2. 通过模拟文本的单元检查验证人民币三种金额规则、美元两种规则和负数金额规则。
3. 实际使用时先以少量可确认的 PDF/水单运行，检查 CSV 后再处理整批文件。
